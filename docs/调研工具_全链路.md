# 小醉桌面研究 v1.0 — 全链路速查

> 入口：`调研工具/main.py`（桌面 GUI）｜核心引擎：`调研工具/engine.py`
> 配置：`调研工具/research_config.json`（本地单一来源）
> 机制细节见 [Wiki](WIKI.md)

---

## 一、产品定位

小醉桌面研究是一套面向单人的桌面调研工具：输入一句调研需求，完成需求澄清、搜索规划、多轮检索、素材筛选、报告撰写与 Word/Excel 交付。

- 只做互联网公开信息研究
- 不执行线下访谈、实地调研、问卷发放
- 不接收本地文件上传；调研需求通过文本框输入
- 不依赖积分、订单或邮件系统

设计原则：**代码管流程、预算、证据和交付；AI 负责提问、规划、写作和复核。**

## 二、界面结构

| 区域 | 作用 |
|------|------|
| 左侧输入区 | 调研需求、页数、报告模式、开始生成 |
| 左侧重试区 | 【重试上次任务】从失败阶段继续 |
| 左侧反馈区 | 澄清回答、计划修改、控制面修改、补搜指令 |
| 调研计划 | 展示澄清问题、调研计划与确认状态 |
| 报告控制面 | 展示报告骨架，支持确认、修改、回炉、补搜 |
| 执行日志 | 实时输出搜索、撰写、编译日志 |
| 配置 | 功能配置、本地部署、常规搜索策略、深度搜索策略 |
| 最终报告 | 打开报告目录、复制路径、反馈并沉淀策略 |

报告模式：

- **常规报告**：使用“常规搜索策略”，走标准调研管线
- **超深度**：强制启用框架涌现与深度调研管线
- **行业搜索**：使用常规策略，但至少 3 个搜索批次并开启自动补搜，不逐企业展开

当前只保留单任务交互与失败重试：排队任务无法参与澄清反问。

## 三、核心链路

```
用户输入需求
  │
  ├─ 1. 输入清洗与意图识别
  ├─ 2. 断点恢复（可选）
  ├─ 3. 超深度模式判断
  │     ├─ 是：框架涌现 → 用户确认 → 深度管线
  │     └─ 否：常规管线
  ├─ 4. 澄清反问（推演引擎分离必问/可推理）
  ├─ 5. 搜索矩阵：批次 × 迭代 × Top K × 预算
  ├─ 6. 调研计划生成 + 用户确认/修改
  ├─ 7. 多轮搜索（DeepSeek Search + GPT Researcher）
  ├─ 8. 覆盖度检查 + 缺口补搜
  ├─ 9. 素材聚类、评分与分层
  ├─ 10. 骨架生成 + 控制面确认/补搜
  ├─ 11. 逐章撰写、事实核查、双向审稿、统稿
  ├─ 12. 质量复核：自检 / 数据防坑 / 来源多样性 / 评分
  └─ 13. Word / Excel / 图表 / 精炼版 / 溯源附录
```

## 四、搜索与抓取

### 搜索

- **GPT Researcher**：主搜索与深度研究，通过 `gptr_service` 产出原始报告；内部 retriever 为 `deepseek`
- **DeepSeek Search**：批次补搜与回退，接口 `https://api.deepseek.com/v1/tools/search`
- **RouteDispatcher**：标准/极致两条路线，决定预算与终止策略

### 抓取

- **DeepSeek Fetch**：高价值网页全文抓取，接口 `https://api.deepseek.com/v1/tools/fetch`
- 深度抓取默认开启；开启时自动启用素材聚类与分层注入
- Playwright 深度抓取连续失败 3 次后，后续 URL 直接走 DeepSeek Fetch
- 网页截图文字识别仅作为抓取失败时的内部兜底，不再解析本地文件

## 五、搜索策略

两套策略分别保存在：

- `research_config_regular.json`
- `research_config_deep.json`

预设文件只保存策略字段，不保存 API Key。主配置 `research_config.json` 始终是运行时单一来源。

| 参数 | 常规默认 | 超深度默认 |
|------|----------|------------|
| 搜索批次 | 2 | 3 |
| 每批迭代 | 2 | 3 |
| 每次搜索取数 Top K | 5 | 10 |
| 搜索密度 Top K | 10 | 15 |
| 预算预设 | 20 | 40 |
| 自动补搜 | 关 | 开 |
| 补搜轮次 | 1 | 3 |
| 每轮补搜信源 | 20 | 10 |

页数统一在左侧设置，配置页不再重复设置页数。实际搜索扣减由 `ResearchState` 统一执行。

## 六、失败与恢复

每个阶段通过 `_run_stage()` 执行：

- 已完成的阶段跳过；
- 超时、连接失败、限流等瞬时错误最多自动重试 2 次（退避 5 秒、15 秒）；
- 非瞬时错误立即失败；
- 核心阶段最终失败写入 `StageFailed`，任务状态落盘；
- `quality` 阶段为非核心，失败记录后继续交付；
- GUI 点击【重试上次任务】后，从失败阶段继续，已写章节直接复用；预算取最近一次阶段快照的值，失败阶段内已消耗但未落盘的预算可能重新计算。

任务状态保存在 `output_dir/任务状态/<task_id>/`：

```
task.json              阶段状态、尝试次数、错误、交付物记录
artifacts/pipeline.json 任务、计划、大纲、章节快照
artifacts/materials.json 已获取素材
chapters/              逐章落盘内容
zero_shot_draft.md     骨架草稿
report.md              当前报告草稿
```

## 七、报告产物

每次成功调研会在输出目录生成：

| 产物 | 说明 |
|------|------|
| Word 报告 | 主报告，含来源附录 |
| 精炼版 Word | 常规版/深度版精简报告 |
| Excel 附录 | 素材来源、数据点与信源等级（S/A/B/C） |
| 图表 | 根据报告内容生成 |
| Dashboard | 调研概览页 |
| 策略文件 | 用户反馈经 LLM 整理后写入 `output/strategy/` |
| 声明账本 | `后台调试/claim_ledger_<task_id>.json` |

## 八、配置说明

| 子页 | 内容 |
|------|------|
| 功能配置 | API Key、Base URL、模型、DeepSeek 搜索接口、输出目录、深度抓取开关 |
| 本地部署 | Ollama Host/Model；未启动时自动降级，不影响主流程 |
| 常规搜索策略 | 批次、迭代、Top K、预算、补搜轮次与信源数 |
| 深度搜索策略 | 更高的批次、迭代、Top K、预算与补搜额度 |

切换报告模式时会自动加载对应策略；点击“保存配置”写入主配置，点击“保存常规/深度策略”写入对应预设并同步当前模式。

首次运行可从示例配置开始：

```powershell
Copy-Item 调研工具\research_config.example.json 调研工具\research_config.json
```

## 九、能力边界

- 仅基于互联网公开信息，不编造线下调研活动
- 不提供知识库注入、积分计费、订单台账、邮件发送
- 不提供本地 OCR 与访谈生成
- 质量评分是工程自检，不是事实仲裁

## 十、运行

```powershell
pip install -r requirements-research.txt
python 调研工具\main.py
```

首次运行需在配置页填写 DeepSeek API Key 并保存；或直接编辑 `调研工具/research_config.json`。

依赖中的 `sv-ttk` 用于 Windows 11 Fluent 风格界面；未安装时自动回退到 ttk 默认主题。

可选服务：

```powershell
# 本地语义检索（不装则回退 BM25）
ollama pull bge-m3

# GPT Researcher 补充检索（本机地址且开启自动拉起时可省略手动启动）
pip install -r gptr_service\requirements.txt
python gptr_service\main.py

# 动态网页渲染（连续失败 3 次后自动切 DeepSeek Fetch）
pip install playwright
playwright install chromium
```
